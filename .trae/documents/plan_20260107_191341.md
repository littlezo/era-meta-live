## 修复 send_follow_list 命令缺少 roomId 字段问题

### 问题分析
根据错误信息和代码检查，发现之前的修复方案有误。正确的问题原因是：

1. 前端发送：`{ followList: [{ roomId: "123", ... }] }`
2. Tauri 2.x 自动转换顶层参数名：`{ follow_list: [{ roomId: "123", ... }] }`
3. 后端 `send_follow_list` 函数接收 `follow_list: Vec<FrontendFollowedStreamer>`
4. 但后端 `FrontendFollowedStreamer` 结构体字段名改为了 camelCase，且没有添加 serde 转换属性
5. serde 默认期望 JSON 字段名与 Rust 字段名匹配，或通过 serde 属性进行转换
6. 导致 serde 无法将 `roomId`（camelCase）转换为 `roomId`（camelCase），因为缺少转换属性

### 修复方案
将后端 `FrontendFollowedStreamer` 结构体的字段名改回 snake_case，并添加 `#[serde(rename_all = "camelCase")]` 属性：

```rust
#[derive(Debug, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct FrontendFollowedStreamer {
    pub platform: String,
    pub room_id: String,
    pub streamer_id: String,
    pub nickname: String,
    pub avatar_url: String,
}
```

### 验证方法
1. 编译 Rust 后端，确保没有编译错误
2. 运行应用，检查是否还有 "missing field `roomId`" 错误
3. 确认关注列表能够成功发送到后端
