# 新版弹幕前端对接修复方案

## 问题分析
通过分析代码，我发现了前端弹幕对接的核心问题：

1. **消息格式不匹配**：
   - 后端 `TauriEventEmitter::emit_message` 方法发送的消息格式是：
     ```json
     { "platform": "douyin", "room_id": "123", "message": {...} }
     ```
   - 前端 `platformApi.subscribeToMessages` 方法期望接收的是 `UnifiedMessage` 格式：
     ```typescript
     interface UnifiedMessage {
       id: string;
       message_type: string;
       room_id: string;
       user: string;
       content: string;
       // ... 其他字段
     }
     ```

2. **类型转换问题**：
   - 前端直接将收到的消息断言为 `UnifiedMessage`，但实际格式不匹配
   - 导致消息无法正确显示

## 修复方案

1. **修改 `platformApiService.ts` 中的 `subscribeToMessages` 方法**：
   - 正确处理后端发送的消息格式
   - 将 `{ platform, room_id, message }` 格式转换为 `UnifiedMessage` 格式
   - 确保类型安全

2. **修改 `messageManager.ts` 中的消息处理逻辑**：
   - 确保正确处理从 `platformApi.subscribeToMessages` 接收到的消息
   - 验证消息格式，避免类型错误

3. **添加类型检查和错误处理**：
   - 在关键位置添加类型检查
   - 处理可能的格式错误，避免应用崩溃

## 实现步骤

1. **修改 `platformApiService.ts`**：
   ```typescript
   // 订阅消息事件
   public async subscribeToMessages(
     callback: (message: UnifiedMessage) => void,
     roomId?: string
   ): Promise<() => void> {
     try {
       const unlisten = await listen<any>('message', (event) => {
         // 处理后端发送的消息格式：{ platform, room_id, message }
         const eventData = event.payload;
         
         // 提取实际消息内容
         let message = eventData;
         if (eventData.message) {
           // 如果包含 message 字段，则是来自后端的包装格式
           message = eventData.message;
           // 添加缺失的平台字段
           if (!message.platform && eventData.platform) {
             message.platform = eventData.platform;
           }
           // 确保 room_id 字段存在
           if (!message.room_id && eventData.room_id) {
             message.room_id = eventData.room_id;
           }
         }
         
         // 验证消息格式
         if (message && typeof message === 'object' && message.content && (!roomId || message.room_id === roomId)) {
           callback(message as UnifiedMessage);
         }
       });
       return unlisten;
     } catch (error) {
       console.error('Failed to subscribe to messages:', error);
       throw error;
     }
   }
   ```

2. **修改 `platformApiService.ts` 中的 `startMessageListener` 和 `stopMessageListener` 方法**：
   - 确保参数名与后端期望的一致
   - 将 `roomId` 改为 `room_id`

3. **修改 `messageManager.ts`**：
   - 添加消息格式验证
   - 确保正确处理各种消息类型

## 预期效果

修复后，前端将能够：
1. 正确接收和处理后端发送的消息
2. 确保消息格式与 `UnifiedMessage` 类型匹配
3. 避免类型错误导致的应用崩溃
4. 正确显示弹幕消息

## 关键实现细节

- **类型安全**：添加类型检查，确保只处理有效的消息
- **错误处理**：添加适当的错误处理，避免应用崩溃
- **向后兼容**：确保修改后的代码能够处理各种可能的消息格式
