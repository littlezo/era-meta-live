# 实现解析后原始消息的返回和存储

## 1. 修改 MessageFrontendPayload 结构体
- 在 `/Volumes/Data/project/era-meta-live/src-tauri/platforms/shared/src/types.rs` 中的 `MessageFrontendPayload` 结构体添加 `raw` 字段
- 字段类型为 `Option<serde_json::Value>`，用于存储解析后的原始消息

## 2. 更新所有消息解析函数
- 修改 `/Volumes/Data/project/era-meta-live/src-tauri/platforms/douyin/src/message/message_parsers.rs` 中的所有解析函数
- 在解析成功后，将解析后的原始消息转换为 `serde_json::Value` 并赋值给 `MessageFrontendPayload.raw` 字段
- 对于不同的消息类型，使用不同的序列化方式：
  - 对于 protobuf 消息，使用 `serde_prost::to_value()` 或手动转换为 JSON
  - 确保原始消息包含足够的调试信息

## 3. 更新消息处理逻辑
- 修改 `/Volumes/Data/project/era-meta-live/src-tauri/platforms/douyin/src/message/message_handler.rs` 中的消息处理逻辑
- 将 `MessageFrontendPayload.raw` 赋值给 `PlatformMessage.raw` 字段
- 确保所有消息类型都正确处理原始消息的传递

## 4. 验证编译通过
- 运行 `cargo check` 确保所有代码编译通过
- 修复可能出现的编译错误

通过以上修改，`message_parsers.rs` 中的解析函数将返回包含原始消息的 `MessageFrontendPayload`，然后在 `message_handler.rs` 中将原始消息赋值给 `PlatformMessage.raw` 字段，实现原始消息的完整传递和存储。
