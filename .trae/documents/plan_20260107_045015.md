## 实现解析后的原始 JSON 消息返回与字段填充

### 需求分析
1. `raw` 字段应该是解析后的原始 JSON 消息，而不是包含 base64 编码的原始字节
2. 所有消息字段需要结合 `douyin.proto` 尽可能填充有效值，而不是简单的 `None`

### 实施步骤

1. **更新消息解析函数**
   - 修改所有消息解析函数，将解析后的 protobuf 消息直接序列化为 JSON 作为 `raw` 字段的值
   - 移除之前的 base64 编码逻辑
   - 确保 `raw` 字段包含完整的解析后消息的 JSON 表示
   - 使用 `serde_json::json!` 宏构建包含所有可用字段的 JSON 对象

2. **更新消息处理逻辑**
   - 修改 `message_handler.rs` 中的代码，结合 `douyin.proto` 的定义
   - 尽可能填充 `PlatformMessage` 的所有字段，包括 `uid`、`badge_name`、`badge_level` 等
   - 从解析后的消息中提取更多有用信息，如用户 ID、徽章信息等
   - 确保所有字段都有合理的默认值，而不是简单的 `None`

3. **处理用户信息**
   - 从 `User` 结构体中提取 `id` 字段作为 `PlatformMessage.uid`
   - 提取用户等级、粉丝牌等级等信息
   - 处理用户徽章信息，填充 `badge_name` 和 `badge_level` 字段

4. **处理礼物信息**
   - 从 `GiftMessage` 中提取礼物名称、数量、价格等信息
   - 填充 `PlatformMessage` 的礼物相关字段

5. **测试和验证**
   - 运行 `cargo check` 确保编译通过
   - 运行 `cargo build` 验证构建成功
   - 确保所有消息类型都能正确返回解析后的原始 JSON 消息
   - 确保 `PlatformMessage` 的所有字段都有合理的值

### 预期结果
- 所有消息解析函数返回的 `MessageFrontendPayload.raw` 字段包含解析后的 protobuf 消息的完整 JSON 表示
- `PlatformMessage` 的所有字段都根据 `douyin.proto` 的定义填充了合理的值
- 前端能够收到完整的解析后原始 JSON 消息和完整的 `PlatformMessage` 对象

### 注意事项
- 确保为所有消息类型添加完整的 JSON 序列化
- 处理好嵌套消息和枚举类型的 JSON 序列化
- 确保 JSON 格式符合预期，便于前端处理
- 保持代码的可读性和可维护性
- 结合 `douyin.proto` 的定义，尽可能填充所有可用字段
