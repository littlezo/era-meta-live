## 问题分析

通过对代码和用户需求的深入分析，我发现当前实现存在以下核心问题：

1. **平台耦合问题**：`platforms/src/watch.rs` 与具体直播平台（抖音、斗鱼等）耦合度太高，违反了通用性原则
2. **消息监听接口设计问题**：`interface.rs` 中的消息监听接口没有返回停止器，而是通过单独的方法停止，不够灵活
3. **主应用业务逻辑问题**：主应用中可能存在业务逻辑，违反了"主应用不应存在业务逻辑"的设计原则
4. **未实现的需求**：之前计划中还有一些未实现的部分，如统一的消息管理进程、消息路由和广播等

## 修复方案

### 1. 解耦 `platforms/src/watch.rs` 与具体平台

#### 1.1 修改 `watch.rs` 中的平台调用逻辑
- **移除直接平台依赖**：不再直接导入和使用具体平台的模块
- **使用平台工厂模式**：通过 `get_global_platform_factory` 获取平台工厂实例
- **统一接口调用**：使用 `LivePlatform` 接口调用平台方法，而不是直接调用平台特定方法

#### 1.2 重新实现主播状态检测逻辑
- **使用统一的 `fetch_room_info` 方法**：通过平台实例的 `fetch_room_info` 方法获取主播状态
- **移除平台特定的状态检测代码**：不再使用 `match platform` 分支处理不同平台的逻辑

#### 1.3 重新实现消息监听启动逻辑
- **使用统一的 `start_message_listener` 方法**：通过平台实例的 `start_message_listener` 方法启动消息监听
- **移除平台特定的消息监听代码**：不再使用 `match platform` 分支处理不同平台的消息监听

### 2. 重新设计消息监听接口

#### 2.1 修改 `LivePlatform` trait 中的消息监听接口
- **添加 `MessageListener` 类型**：定义一个包含 `stop` 方法的 `MessageListener` 类型
- **修改 `start_message_listener` 方法**：使其返回 `Result<Box<dyn MessageListener>, PlatformError>`
- **移除 `stop_message_listener` 方法**：不再需要单独的停止方法

#### 2.2 实现 `MessageListener` trait
```rust
// 消息监听器 trait，用于停止消息监听
pub trait MessageListener: Send + Sync {
    // 停止消息监听
    async fn stop(&mut self) -> Result<(), PlatformError>;
    
    // 获取监听器状态
    fn status(&self) -> ListenerStatus;
    
    // 获取消息计数
    fn message_count(&self) -> u32;
}
```

### 3. 确保主应用不包含业务逻辑

#### 3.1 简化 `src-tauri/src/watch.rs`
- **移除业务逻辑**：将其改造为 `platforms::watch` 模块的简单封装
- **实现 `EventEmitter` 适配器**：将 `platforms` 模块的事件传递到主应用
- **简化 API**：确保主应用只提供必要的接口，不包含业务逻辑

#### 3.2 更新 `src-tauri/src/platform_commands.rs`
- **移除手动消息监听命令**：删除 `start_message_listener` 和 `stop_message_listener` 命令
- **添加消息监听状态查询接口**：实现 `get_message_listener_status` 命令

### 4. 实现未完成的需求

#### 4.1 实现统一的消息管理进程
- **创建 `message_manager.rs`**：实现统一的消息管理接口
- **管理所有平台的消息监听器**：实现消息监听器的统一管理
- **提供消息统计和状态查询**：实现消息统计和状态查询功能

#### 4.2 实现消息路由和广播
- **实现消息路由逻辑**：根据平台和房间 ID 路由消息
- **实现消息广播功能**：支持向多个客户端广播消息
