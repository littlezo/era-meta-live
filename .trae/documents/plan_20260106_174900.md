# 抖音API响应处理和日志系统修复计划

## 1. 抖音API响应处理逻辑修复

### 问题分析
当抖音API响应中`data.data`为空时，当前代码直接返回错误，没有尝试从`data.user`中获取主播信息。根据终端日志，API返回了完整的`data.user`信息，包含主播的nickname、avatar等关键数据。

### 修复方案
- **位置**：platforms/douyin/src/web_api.rs:198-235
- **修改内容**：当`room`不存在时，创建一个默认的room对象，并从`data.user`中提取主播信息
- **逻辑**：
  1. 如果`room`存在，按照原逻辑处理
  2. 如果`room`不存在，创建一个空的room对象
  3. 从`data.user`中提取主播信息（nickname、avatar等）
  4. 将提取的信息添加到空的room对象中
  5. 返回包含主播信息的room对象，而不是返回错误

## 2. 日志系统初始化修复

### 问题分析
当前日志系统初始化时，打印的日志文件路径是相对路径，用户要求打印绝对路径以便于查找日志文件。

### 修复方案
- **位置**：platforms/shared/src/logger.rs:89-135
- **修改内容**：将相对的日志文件路径转换为绝对路径，然后在日志系统初始化完成后打印
- **逻辑**：
  1. 使用`std::fs::canonicalize`或`std::path::Path`将相对路径转换为绝对路径
  2. 在日志系统初始化成功后，使用`info!`宏打印完整的绝对日志文件路径
  3. 确保在所有初始化路径中都能打印绝对路径

## 预期效果

1. **抖音API修复后**：即使`data.data`为空，API调用也能成功返回包含主播信息的响应，提高了系统的鲁棒性

2. **日志系统修复后**：日志系统初始化完成后，会在日志中记录完整的绝对日志文件路径，便于开发者查找和分析日志文件

### 2. 日志系统初始化修复
```rust
// 获取按天命名的日志文件路径
let log_file_path = format!("{}/platforms-{}.log", config.log_dir, Local::now().format("%Y-%m-%d"));

// 将相对路径转换为绝对路径
let log_file_path = std::fs::canonicalize(log_file_path)
    .map(|p| p.display().to_string())
    .unwrap_or(log_file_path);

// 在日志系统初始化成功后打印绝对日志文件路径
match registry.try_init() {
    Ok(_) => {
        info!("日志系统初始化成功，日志文件: {}", log_file_path);
        info!("日志级别: {:?}", config.level);
        info!("完整绝对日志文件路径: {}", log_file_path);
    },
    Err(e) => {
        eprintln!("日志系统初始化失败或已存在: {}", e);
        // 日志系统可能已被Tauri初始化，忽略此错误
        // 但仍需打印绝对日志文件路径
        eprintln!("日志文件路径: {}", log_file_path);
    }
}
```
