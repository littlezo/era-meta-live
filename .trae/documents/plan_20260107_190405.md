## 修复弹幕前端集成错误

### 问题分析
根据错误信息和代码检查，发现两个主要问题：

1. **Command fetch_categories not found**
   - 后端 `platform_commands.rs` 中定义了 `fetch_categories` 函数
   - 但 `main.rs` 的 `invoke_handler` 中没有注册这个命令

2. **invalid args `followList` for command `send_follow_list`: missing field `roomId`**
   - 前端发送的是 camelCase 字段名（如 `roomId`）
   - 后端 `FrontendFollowedStreamer` 结构体使用的是 snake_case 字段名（如 `room_id`）
   - 虽然添加了 `#[serde(rename_all = "camelCase")]` 属性，但可能存在配置或理解问题

### 修复方案

#### 1. 注册 fetch_categories 命令
在 `main.rs` 的 `invoke_handler` 中添加 `platform_commands::fetch_categories` 注册：

```rust
.invoke_handler(tauri::generate_handler![
    // Unified platform commands (preferred)
    platform_commands::fetch_live_list,
    platform_commands::fetch_room_info,
    platform_commands::get_stream_url,
    platform_commands::fetch_streamer_info,
    platform_commands::search_rooms,
    platform_commands::fetch_categories, // 添加这行
    platform_commands::get_message_listener_status,  // Unified message status query
    platform_commands::send_follow_list,  // Follow list management
    // ... 其他命令
])
```

#### 2. 修复 send_follow_list 字段名匹配问题
将后端 `FrontendFollowedStreamer` 结构体的字段名改为 camelCase，与前端发送的一致：

```rust
#[derive(Debug, Deserialize)]
pub struct FrontendFollowedStreamer {
    pub platform: String,
    pub roomId: String, // 从 room_id 改为 roomId
    pub streamerId: String, // 从 streamer_id 改为 streamerId
    pub nickname: String,
    pub avatarUrl: String, // 从 avatar_url 改为 avatarUrl
}
```

### 验证方法
1. 编译 Rust 后端，确保没有编译错误
2. 编译前端项目，确保没有类型错误
3. 运行应用，检查是否还有 "Command fetch_categories not found" 和 "missing field `roomId`" 错误
4. 确认关注列表能够成功发送到后端
5. 确认分类列表能够成功获取
