## 1. 项目概述

### 1.1 项目背景

本项目涉及重构一个多平台直播应用，目标是创建一个统一的直播平台接入层，覆盖所有平台（Bilibili、Douyin、Douyu、Huya），实现统一的API接口、日志系统和代码规范。

### 1.2 核心目标

1. 增强平台统一日志系统，实现每日日志轮转、持久化和可配置性
2. 将抖音相关构建代码迁移到 platforms/douyin/build.rs
3. 清理主 build.rs，移除抖音特定代码
4. 改进错误处理，支持错误源追踪和嵌套错误
5. 替换 log4rs 为 tracing 生态系统
6. 增强所有平台关键模块的日志记录
7. 统一各平台的日志风格和初始化方式
8. 统一前端代码结构，减少平台特定代码
9. 实现统一的API调用方式
10. 统一术语和命名规范

## 2. 平台接入层统一

### 2.1 接入层设计规范

#### 2.1.1 文件命名规范

| 功能模块 | 统一文件名 | 说明 |
|---------|-----------|------|
| 直播列表 | live_list.rs | 获取平台直播列表 |
| 房间信息 | room_info.rs | 获取直播间详细信息 |
| 主播信息 | streamer_info.rs | 获取主播详细信息 |
| 弹幕消息 | message.rs | 弹幕消息监听和处理 |
| 流地址获取 | stream_url.rs | 获取直播流地址 |
| 搜索功能 | search.rs | 搜索直播间或主播 |
| 分类信息 | categories.rs | 获取平台分类信息 |
| 平台模型 | models.rs | 平台特定数据模型 |
| 认证功能 | auth.rs | 平台认证相关功能 |

#### 2.1.2 模块结构规范

每个平台目录下采用统一的模块结构：

```
platform_name/
├── src/
│   ├── lib.rs          # 平台主实现
│   ├── live_list.rs    # 直播列表功能
│   ├── room_info.rs    # 房间信息功能
│   ├── streamer_info.rs # 主播信息功能
│   ├── message.rs      # 弹幕消息功能
│   ├── stream_url.rs   # 流地址获取功能
│   ├── search.rs       # 搜索功能
│   ├── categories.rs   # 分类信息功能
│   ├── models.rs       # 数据模型
│   └── auth.rs         # 认证功能
└── Cargo.toml
```

#### 2.1.3 函数命名规范

统一函数命名格式：

```rust
// 平台特定功能函数
sync/async fn [action]_[platform]_[resource](...) -> Result<...>

// 示例
async fn fetch_bilibili_live_list(...) -> Result<...>
async fn fetch_douyin_room_info(...) -> Result<...>
```

#### 2.1.4 术语统一

| 术语 | 统一使用 | 避免使用 |
|------|----------|----------|
| 直播间 | room | anchor_room, live_room |
| 主播 | streamer | anchor, owner, user |
| 观众数 | viewer_count | watching, hot, user_count |
| 直播状态 | live_status | status, is_live |
| 封面图 | cover_url | cover |
| 头像 | avatar_url | avatar |

6. **统一函数命名**：按照统一规范重命名各平台的函数

8. **测试和验证**：编译测试，功能测试，集成测试

## 6. 开发模式修复

### 6.1 修复 Terminal#1-225 中的编译错误

#### 6.1.1 分析当前错误

1. **Bilibili live_list.rs 错误**
   - `E0599`: 方法 `header` 未找到，因为 `get` 方法返回的是 `Future` 而不是 `RequestBuilder`

   - `E0308`: 类型不匹配 - 期望 `&Client`，但得到 `&Arc<HttpClient>`
   - 发生在 `fetch_web_stream_data` 调用（第492和563行）

3. **Bilibili lib.rs 错误**
   - `E0308`: 类型不匹配 - 期望 `&Client`，但得到 `&Arc<HttpClient>`

2. **修复 Huya stream_url.rs**
   - 修改 `fetch_web_stream_data` 函数签名以接受 `&HttpClient`
