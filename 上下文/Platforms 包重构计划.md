# Platforms 包重构计划

## 1. 重构目标
- 将 platforms 包从 Tauri 应用中解耦
- 设计模块化的直播平台架构
- 提供统一的 API 接口和服务层
- 支持快速扩展新平台
- 调整命名规范，将 "danmuke" 统一更名为 "message"

## 2. 架构设计

### 2.1 模块结构
```
src-tauri/
├── platforms/core           # 主平台包（统一接口层）
├── platforms/bilibili/      # Bilibili 平台独立 crate
├── platforms/douyin/        # Douyin 平台独立 crate
├── platforms/douyu/         # Douyu 平台独立 crate
├── platforms/huya/          # Huya 平台独立 crate
├── platforms/shared/        # 通用工具和数据模型
└── platforms/rpc/           # RPC 服务层
```

### 2.2 核心抽象设计
1. **定义统一平台 Trait**：
   - `LivePlatform` trait 定义各平台必须实现的接口
   - 包含直播流获取、弹幕监听、消息发送等核心功能

2. **数据模型标准化**：
   - 统一的直播流信息结构
   - 统一的消息（弹幕）数据结构
   - 统一的错误类型

3. **平台注册机制**：
   - 支持动态注册和发现平台实现
   - 提供平台工厂方法

## 3. 实施步骤

### 3.1 准备工作
1. **创建 workspace 配置**：
   - 更新 src-tauri/platforms/Cargo.toml 为 workspace 配置

2. **创建核心模块**：
   - 创建 platforms/core 目录和基础结构
   - 定义 LivePlatform trait 和核心数据模型

### 3.2 迁移现有代码
1. **创建各平台独立 crate**：
   - 为每个平台创建独立的 Cargo.toml
   - 调整目录结构：将每个平台的 src 目录移动到对应 crate 下

2. **迁移 shared 模块**：
   - 将原 common 模块迁移到 shared crate
   - 统一数据模型和工具函数

3. **移除 Tauri 依赖**：
   - 检查并移除平台代码中对 Tauri 的直接依赖
   - 替换为通用依赖或抽象接口

### 3.3 实现统一接口层
1. **定义核心 Trait**：
   - 在 core crate 中定义 LivePlatform trait
   - 包含直播流获取、弹幕监听、消息处理等方法

2. **平台适配**：
   - 为每个平台实现 LivePlatform trait
   - 统一数据格式转换

### 3.4 实现 RPC 服务层
1. **设计 RPC 接口**：
   - 定义 gRPC/JSON-RPC 接口
   - 支持跨语言调用

2. **实现服务端**：
   - 基于统一接口层实现 RPC 服务
   - 支持异步调用和流式传输

### 3.5 命名规范调整
1. **术语统一**：
   - 将 "danmuke" 统一更名为 "message"
   - 更新所有相关接口和数据模型

2. **接口命名标准化**：
   - 统一消息、弹幕相关接口命名
   - 确保各平台接口命名一致

## 4. 依赖管理
- 使用 Cargo workspace 管理多 crate 依赖
- 共享依赖版本管理
- 确保各平台 crate 独立可编译

## 5. 验证测试
1. **单元测试**：
   - 为核心接口和功能编写单元测试
   - 确保各平台实现的正确性

2. **集成测试**：
   - 测试统一接口层的可用性
   - 测试 RPC 服务的正确性

3. **兼容性测试**：
   - 确保重构后的代码与原有 Tauri 应用兼容

## 6. 预期成果
- 解耦的平台模块，可独立编译和使用
- 统一的平台接口，支持快速扩展新平台
- 跨语言 RPC 支持，方便前端集成
- 标准化的命名规范，提高代码可维护性

## 7. 风险评估
- **依赖调整风险**：移除 Tauri 依赖可能导致部分功能需要重新实现
- **接口设计风险**：统一接口可能无法覆盖所有平台的特殊功能
- **测试覆盖风险**：需要确保充分的测试覆盖，避免回归问题

## 8. 后续优化方向
- 支持更多直播平台
- 优化 RPC 服务性能
- 提供更丰富的平台功能支持
- 完善文档和示例代码
