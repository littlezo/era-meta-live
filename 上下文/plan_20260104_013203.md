## 问题分析

当前弹幕消息监听错误的根本原因是：

1. Douyin 平台的 `fetch_room_from_api` 函数直接使用 `http_client.inner.get()`，绕过了 `HttpClient` 包装器方法
2. 该函数没有设置 `Accept` 头来请求 JSON 格式
3. 服务器返回 HTML 而不是 JSON，导致 `.json()` 方法解析失败
4. 这种失败被传播为包含状态码 200 OK 的错误

## 修复方案

1. **修改 `src-tauri/platforms/douyin/src/web_api.rs`**：
   - 在 `fetch_room_from_api` 函数中添加 `Accept` 头，明确请求 JSON 格式
   - 使用 `HttpClient` 包装器方法而不是直接调用 `inner.get()`
   - 改进错误处理，区分 HTTP 状态错误和 JSON 解析错误

2. **修改 `src-tauri/platforms/douyin/src/message/websocket_connection.rs`**：
   - 确保 WebSocket 连接函数正确处理可能的错误情况
   - 增加更详细的错误日志，便于调试

3. **修改 `src-tauri/platforms/douyin/src/message/web_fetcher.rs`**：
   - 改进 `collect_cookies_and_ids` 函数，确保收集到有效的 cookie
   - 增加 cookie 验证逻辑

## 预期效果

修复后，Douyin 消息监听将能够：

1. 正确请求 JSON 格式的响应
2. 区分 HTTP 状态错误和 JSON 解析错误
3. 收集和使用有效的 cookie
4. 更可靠地建立 WebSocket 连接
5. 提供更详细的错误日志

## 关键实现细节

1. **在 `web_api.rs` 中**：
   ```rust
   // 添加 Accept 头
   headers.insert(ACCEPT, HeaderValue::from_static("application/json, text/plain, */*"));
   ```

2. **在 `web_api.rs` 中**：
   ```rust
   // 使用 HttpClient 包装器方法
   let json = http_client
       .get_json(&api)
       .await
       .map_err(|e| format!("Failed to fetch room data: {}", e))?;
   ```

3. **在 `websocket_connection.rs` 中**：
   ```rust
   // 改进错误处理
   if let Err(e) = connect_async(client_request).await {
       return Err(format!("WebSocket connection failed: {}", e));
   }
   ```
