# Platforms 包重构计划

## 1. 架构设计

### 1.1 核心架构

```
platforms/
├── core/              # 核心抽象层
│   ├── src/
│   │   ├── lib.rs
│   │   ├── traits.rs  # 统一平台接口定义
│   │   ├── models.rs  # 标准化数据模型
│   │   ├── registry.rs # 平台注册和发现机制
│   │   └── error.rs   # 统一错误处理
├── implementations/   # 各平台实现
│   ├── bilibili/
│   ├── douyin/
│   ├── douyu/
│   └── huya/
├── rpc/               # RPC 服务层
│   ├── src/
│   │   ├── lib.rs
│   │   ├── grpc/
│   │   └── json_rpc/
├── shared/            # 共享工具和类型
│   └── src/
└── Cargo.toml         # 主包配置
```

### 1.2 核心组件

#### 1.2.1 统一平台接口（traits.rs）

定义以下核心 trait：

- `LivePlatform`：平台基础信息和注册
- `LiveStreamService`：直播流相关操作
- `MessageService`：弹幕/消息相关操作
- `StreamerService`：主播信息相关操作
- `SearchService`：搜索功能

#### 1.2.2 标准化数据模型（models.rs）

统一以下数据结构：

- `LiveStream`：直播流信息
- `Streamer`：主播信息
- `Category`：分类信息
- `Message`：弹幕/消息
- `SearchResult`：搜索结果

#### 1.2.3 平台注册机制（registry.rs）

实现：

- 静态注册：编译时注册平台
- 动态注册：运行时注册平台
- 平台发现：通过名称或 ID 获取平台实例

#### 1.2.4 统一错误处理（error.rs）

定义：

- `PlatformError` 枚举：包含各种平台错误类型
- 统一的错误转换机制
- 详细的错误信息和代码

## 2. 实现步骤

### 2.1 阶段一：核心架构搭建

1. 创建 `core` 模块，定义统一接口和数据模型
2. 实现平台注册和发现机制
3. 设计统一错误处理
4. 重构 `shared` 模块，移除 Tauri 依赖

### 2.2 阶段二：平台实现迁移

1. 重构各平台实现，使其符合新的抽象接口
2. 移除平台实现中的 Tauri 依赖
3. 统一各平台的数据模型转换
4. 实现平台特定的错误处理

### 2.3 阶段三：RPC 服务层实现

1. 添加 gRPC 支持：
   - 定义 Protobuf 服务和消息
   - 实现 gRPC 服务端
   - 生成客户端代码

2. 添加 JSON-RPC 支持：
   - 实现 JSON-RPC 服务端
   - 支持 HTTP 和 WebSocket 传输

3. 实现 API 网关：
   - 统一请求处理
   - 认证和授权
   - 日志和监控

### 2.4 阶段四：集成和测试

1. 集成各平台实现到核心架构
2. 编写单元测试和集成测试
3. 测试 RPC 服务的跨语言调用
4. 性能测试和优化

## 3. 关键技术点

### 3.1 依赖管理

- 移除 `tauri` 依赖
- 使用轻量级依赖，保持通用性
- 支持异步和同步 API

### 3.2 模块化设计

- 清晰的模块边界
- 低耦合，高内聚
- 支持独立编译和测试

### 3.3 扩展性

- 新平台可以通过实现核心 trait 快速集成
- 支持插件化扩展
- 灵活的配置系统

### 3.4 跨语言支持

- gRPC 支持多种语言
- JSON-RPC 易于集成到各种客户端
- 提供详细的 API 文档

## 4. 预期成果

1. 移除了 Tauri 依赖，平台代码可以独立使用
2. 统一的 API 接口，简化了前端和其他服务的调用
3. 模块化架构，支持快速添加新平台
4. 提供 gRPC/JSON-RPC 接口，支持跨语言调用
5. 标准化的数据模型，减少了数据转换的复杂性
6. 统一的错误处理，提高了系统的可维护性

## 5. 后续优化方向

1. 添加缓存机制，提高性能
2. 实现负载均衡和故障转移
3. 添加监控和统计功能
4. 支持更多的直播平台
5. 优化 RPC 服务的性能和安全性
