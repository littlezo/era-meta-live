# 修复直播平台接入层问题

## 问题分析

1. **主播状态异常**：
   - 前端组件使用 `!!res.live_status && res.live_status_detail === 'LIVE'` 来判断直播状态
   - 但统一API服务返回的 `UnifiedRoomInfo` 接口中，`live_status` 是布尔值，而 `live_status_detail` 是枚举值
   - 可能存在平台实现不一致，导致某些平台的 `live_status` 或 `live_status_detail` 字段返回值不符合预期

2. **无法进入直播流详情**：
   - 路由配置中使用了统一的 `Player` 路由 `/:platform/:roomId`
   - 但在某些地方可能仍然使用了旧的平台特定路由，导致路由不匹配

3. **统一API服务实现问题**：
   - 某些方法直接抛出错误，没有完善的错误处理机制
   - 不同平台的实现可能存在差异，导致返回数据格式不一致

## 修复方案

### 1. 修复主播状态判断逻辑

**修改 `FollowsList/index.vue`**：
- 简化直播状态判断逻辑，只依赖 `live_status` 布尔值
- 添加更详细的日志记录，便于调试

**修改 `player/index.vue`**：
- 确保在调用 `platformApi.getStreamUrl` 后，正确处理返回的 `room_info`
- 如果 `room_info` 不存在，不默认将 `playerIsLive.value` 设置为 `true`，而是尝试通过 `fetchRoomInfo` 获取直播状态

### 2. 修复路由配置问题

**检查所有组件中的路由跳转**：
- 确保所有组件都使用统一的 `Player` 路由格式 `/:platform/:roomId`
- 检查 `MainLayout.vue`、`Header.vue` 等组件中的路由跳转逻辑

### 3. 完善统一API服务

**修改 `platformApiService.ts`**：
- 为所有方法添加完善的错误处理机制，避免应用崩溃
- 确保所有平台返回的数据格式一致，特别是 `live_status` 和 `live_status_detail` 字段
- 添加更详细的日志记录，便于调试

### 4. 修复分类获取API

**完善 `fetchCategories` 方法**：
- 为所有平台实现完整的分类获取逻辑
- 确保返回的数据格式一致

### 5. 测试和验证

- 测试所有平台的直播状态显示是否正确
- 测试是否能正常进入直播流详情
- 测试应用在各种情况下是否能正常运行，不会崩溃

## 实施步骤

1. 首先修复 `platformApiService.ts` 中的错误处理机制
2. 然后修复前端组件中的直播状态判断逻辑
3. 接着检查和修复路由配置问题
4. 完善分类获取API的实现
5. 最后进行全面的测试和验证

## 预期效果

- 主播状态显示正确，不会出现异常
- 能够正常进入直播流详情
- 应用在各种情况下都能正常运行，不会崩溃
- 各平台的实现更加统一，便于维护和扩展
