# 逐步实现 platforms 库重构计划

## 1. 移除 Tauri 依赖
- **阶段 1**: 移除所有 `#[tauri::command]` 宏和 `tauri::State` 依赖
- **阶段 2**: 替换 `tauri::AppHandle` 和 `tauri::Emitter` 为自定义的事件广播机制
- **阶段 3**: 替换 `tauri::async_runtime::spawn_blocking` 为标准的 `tokio::task::spawn_blocking`
- **阶段 4**: 移除 `tauri::WebviewWindowBuilder` 相关功能，或替换为独立的浏览器窗口实现

## 2. 迁移 API 接口
- **阶段 1**: 为每个平台创建 `Platform` trait 实现，封装现有的功能
- **阶段 2**: 修改现有的命令式 API，使其调用新的 Platform trait 实现
- **阶段 3**: 逐步废弃旧的命令式 API，推广使用新的 Platform trait 接口

## 3. 实现 RPC 服务层
- **阶段 1**: 选择 RPC 框架（如 tonic 或 jsonrpsee）
- **阶段 2**: 定义 gRPC/JSON-RPC 服务接口
- **阶段 3**: 实现 RPC 服务端，封装 Platform trait 功能
- **阶段 4**: 实现 RPC 客户端，用于主应用调用

## 4. 支持独立运行
- **阶段 1**: 添加 `main` 函数，支持独立运行
- **阶段 2**: 实现配置文件加载和命令行参数解析
- **阶段 3**: 实现服务发现和健康检查

## 5. 实现两种集成模式
- **阶段 1**: 设计本地模式和远程模式的架构
- **阶段 2**: 实现本地模式，直接在主应用中调用库函数
- **阶段 3**: 实现远程模式，通过 RPC 调用独立运行的实例
- **阶段 4**: 实现模式切换和配置管理

## 执行顺序
1. 首先从 Bilibili 平台开始，逐步移除 Tauri 依赖
2. 实现 Bilibili 的 Platform trait 完整实现
3. 依次迁移其他平台（Douyin、Huya、Douyu）
4. 实现 RPC 服务层
5. 实现独立运行模式
6. 实现主应用的两种集成模式

## 关键技术点
- 使用 `async-trait` 实现异步 trait
- 使用 `broadcast` 通道实现事件广播
- 使用 `tonic` 或 `jsonrpsee` 实现 RPC
- 使用 `tokio` 实现异步运行时
- 使用 `clap` 实现命令行参数解析
