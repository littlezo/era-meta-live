# Platforms 统一日志适配与记录计划

## 1. 现状分析
- 所有平台已创建 `Logger` 实例
- 部分平台已有基础日志记录
- WebSocket 日志实现不一致（Bilibili 使用自定义宏，其他平台记录较少）
- HTTP 请求/响应日志记录不完整
- 关键模块日志需要增强

## 2. 目标
- 所有平台使用统一的日志记录方式
- 完整记录关键模块的日志信息
- 标准化日志格式和级别

## 3. 实现计划

### 3.1 统一日志记录标准

#### 3.1.1 日志级别规范
- **Trace**: 详细的调试信息（如 WebSocket 原始消息）
- **Debug**: 模块级别的调试信息（如函数调用参数）
- **Info**: 重要的业务流程信息（如 API 调用成功）
- **Warn**: 警告信息（如重试、降级）
- **Error**: 错误信息（如 API 调用失败、认证错误）

#### 3.1.2 日志格式规范
- 统一使用 `logger.{level}(format!("{}", message))`
- 包含关键上下文信息：平台、模块、方法、参数、结果

### 3.3 关键模块日志增强

#### 3.3.1 HTTP 请求/响应
- **请求日志**: URL、方法、参数、头信息
- **响应日志**: 状态码、响应时间、响应数据（关键字段）
- **错误日志**: 详细的错误信息、重试次数

#### 3.3.2 WebSocket 连接/消息
- **连接日志**: 连接建立、关闭、重连
- **消息日志**: 发送/接收的关键消息内容
- **错误日志**: 连接错误、消息解析错误

#### 3.3.3 消息监听
- **启动/停止日志**: 监听器的启动和停止
- **消息处理日志**: 接收到的消息类型和处理结果
- **错误日志**: 消息处理失败

#### 3.3.4 流地址获取
- **请求日志**: 房间 ID、请求参数
- **响应日志**: 流地址、质量、类型
- **测试日志**: 流地址可用性测试结果

#### 3.3.5 认证流程
- **认证状态日志**: 开始认证、认证成功/失败
- **Token 日志**: Token 获取、刷新、过期
- **错误日志**: 认证失败原因
