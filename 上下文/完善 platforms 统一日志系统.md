# 统一日志系统完善与 build.rs 代码迁移

## 改进目标
1. **完善日志系统**：实现日志持久化、可配置性和结构化，按天轮转日志
2. **统一错误处理**：确保所有错误都经过统一处理和日志记录
3. **代码结构优化**：将抖音相关的 build 代码迁移到对应平台目录

## 改进计划

### 1. 日志系统增强

#### 1.1 日志持久化
- **实现方式**：使用 `log4rs` 或 `tracing-appender` 实现日志持久化
- **配置项**：
  - 日志文件路径（默认：`logs/platforms-{date}.log`）
  - 日志轮转策略：**按天**（每天生成新日志文件）
  - 日志文件保留数量（默认：7个，保留最近7天）
  - 日志文件压缩（可选，默认：不压缩）
- **实现位置**：`shared/src/logger.rs`

#### 1.2 日志可配置性
- **配置文件**：创建 `platforms/log_config.toml` 配置文件
- **配置项**：
  - 日志级别（全局/按平台/按模块）
  - 日志格式（文本/JSON）
  - 持久化开关
  - 控制台输出开关
  - 按天轮转配置
  - 日志保留天数
- **动态配置**：支持运行时重新加载配置

#### 1.3 结构化日志
- **实现方式**：增强现有 `Logger` 实现，支持结构化日志
- **日志字段**：
  - 时间戳（精确到毫秒）
  - 平台名称
  - 模块名称
  - 方法名称
  - 日志级别
  - 执行时间
  - 请求详情
  - 响应状态
  - 错误信息及堆栈

### 2. 统一错误处理

#### 2.1 增强 PlatformError
- 添加错误源追踪
- 支持嵌套错误
- 提供完整的错误信息格式化

#### 2.2 错误转换宏
- 实现 `map_err_to_platform!` 宏，简化错误转换
- 自动记录转换后的错误日志

### 3. build.rs 代码迁移

#### 3.1 移动抖音相关 build 代码
- **从**：`/Volumes/Data/project/era-meta-live/src-tauri/build.rs`（第5-16行）
- **到**：`/Volumes/Data/project/era-meta-live/src-tauri/platforms/douyin/build.rs`

  - 更新路径引用（使用相对路径）
  - 确保 prost_build 配置正确

#### 3.2 主 build.rs 清理
- 移除抖音相关的 build 代码
- 保留 tauri_build::build() 调用

### 4. 完善各平台日志覆盖

#### 4.1 确保所有平台使用统一日志
- Bilibili
- Douyin
- Douyu
- Huya

#### 4.2 关键模块日志增强
- HTTP 请求/响应
