## 重构目标
1. 将每个平台设计为独立子包，便于扩展新平台
2. 设计统一的平台接口，抹平平台差异
3. 实现统一的调用方式
4. 移除Tauri依赖，使platforms库可独立使用

## 实现方案

### 1. 目录结构设计（每个平台作为独立子包）

### 2. 核心类型设计

#### 统一平台抽象trait
```rust
pub trait Platform {
    /// 获取平台名称
    fn name(&self) -> &str;
    
    /// 获取平台类型
    fn platform_type(&self) -> PlatformType;
    
    /// 获取主播信息
    async fn fetch_streamer_info(&self, room_id: &str) -> Result<StreamerInfo, PlatformError>;
    
    /// 获取直播流地址
    async fn fetch_live_stream(&self, room_id: &str, quality: Option<Quality>) -> Result<LiveStream, PlatformError>;
    
    /// 获取直播列表
    async fn fetch_live_list(&self, category: Option<&str>, page: u32) -> Result<Vec<StreamerInfo>, PlatformError>;
    
    /// 搜索主播/直播间
    async fn search(&self, keyword: &str, page: u32) -> Result<Vec<StreamerInfo>, PlatformError>;
    
    /// 启动弹幕监听
    async fn start_danmaku_listener(
        &self,
        room_id: &str,
        callback: Box<dyn FnMut(DanmakuMessage) + Send + 'static>
    ) -> Result<ListenerHandle, PlatformError>;
    
    /// 停止弹幕监听
    async fn stop_danmaku_listener(&self, handle: ListenerHandle) -> Result<(), PlatformError>;
}
```

#### 统一数据模型
```rust
// 平台类型
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum PlatformType {
    Bilibili,
    Douyin,
    Douyu,
    Huya,
}

// 直播状态
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LiveStatus {
    Offline,
    Live,
    Unknown,
}

// 清晰度选项
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Quality {
    Auto,
   原画,
   超清,
   高清,
   流畅,
    Other(String),
}

// 主播信息
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct StreamerInfo {
    pub platform: PlatformType,
    pub room_id: String,
    pub title: String,
    pub anchor_name: String,
    pub avatar: Option<String>,
    pub status: LiveStatus,
    pub category: Option<String>,
    pub viewers: Option<u64>,
}

// 直播流信息
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct LiveStream {
    pub streamer: StreamerInfo,
    pub url: String,
    pub quality: Quality,
    pub available_qualities: Vec<Quality>,
    pub upstream_url: Option<String>,
}

// 弹幕消息
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct DanmakuMessage {
    pub user: String,
    pub content: String,
    pub timestamp: u64,
    pub user_level: Option<i32>,
    pub fans_level: Option<i32>,
}
```

#### 平台工厂
```rust
pub struct PlatformFactory {
    http_client: HttpClient,
}

impl PlatformFactory {
    pub fn new(http_client: HttpClient) -> Self {
        Self { http_client }
    }
    
    pub fn create_platform(&self, platform_type: PlatformType) -> Box<dyn Platform + Send + Sync> {
        match platform_type {
            PlatformType::Bilibili -> Box::new(BilibiliPlatform::new(&self.http_client)),
            PlatformType::Douyin -> Box::new(DouyinPlatform::new(&self.http_client)),
            PlatformType::Douyu -> Box::new(DouyuPlatform::new(&self.http_client)),
            PlatformType::Huya -> Box::new(HuyaPlatform::new(&self.http_client)),
        }
    }
}
```

### 3. 实现步骤

1. **创建统一的类型定义**
   - 设计并实现统一的数据模型
   - 定义Platform trait和相关错误类型

2. **重构现有平台实现**
   - 将每个平台迁移到独立子包
   - 为每个平台实现Platform trait
   - 移除Tauri依赖，使用标准Rust错误处理

3. **实现平台工厂**
   - 创建PlatformFactory，用于创建平台实例
   - 实现动态平台创建和管理

4. **更新Tauri主应用**
   - 使用新的平台工厂调用平台功能
   - 移除直接的platforms库依赖
   - 更新命令处理逻辑

### 4. 扩展新平台的流程

1. 创建新的平台子包目录
2. 实现Platform trait
3. 在PlatformType枚举中添加新类型
4. 在PlatformFactory中添加新平台的创建逻辑
5. （可选）实现平台特定的扩展功能

## 预期收益
1. **易于扩展**：新增平台只需实现统一trait，无需修改现有代码
2. **统一接口**：上层应用使用统一API，无需关心具体平台
3. **低耦合**：平台实现与上层应用解耦，可独立开发和测试
4. **更好的维护性**：每个平台作为独立子包，代码结构清晰
5. **可独立使用**：platforms库可作为独立库使用，不依赖Tauri
