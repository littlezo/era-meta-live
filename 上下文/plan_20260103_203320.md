# 完善直播平台日志体系计划

## 问题分析

当前直播平台接入层存在以下问题：
1. 日志体系不统一，各平台日志实现不一致
2. 缺乏集中的日志管理和配置
3. 前端无法查看API原始数据，调试困难
4. 错误处理和日志记录不够详细

## 解决方案

### 1. 增强后端日志体系

#### 1.1 创建集中式日志工具
- 在 `src-tauri/platforms/shared/src/` 下创建 `logger.rs` 模块
- 实现统一的日志接口，支持不同日志级别
- 添加请求/响应日志记录功能
- 支持原始数据日志记录

#### 1.2 增强API响应结构
- 确保所有API响应都包含原始数据
- 完善 `ApiResponse` 结构，确保 `raw` 字段正确填充
- 为所有平台实现增强版方法，支持返回原始数据

#### 1.3 为各平台添加详细日志
- 在所有平台方法中添加统一的日志记录
- 记录请求参数、响应结果和错误信息
- 添加时间戳和平台标识
- 记录原始API响应数据

### 2. 更新前端代码

#### 2.1 修改 `platformApiService.ts`
- 更新API响应类型，确保包含原始数据
- 添加配置选项，支持开启/关闭原始数据打印
- 在所有API调用中添加详细日志
- 打印原始API响应数据

#### 2.2 增强组件日志
- 在关键组件中添加原始数据日志
- 添加调试开关，控制日志输出
- 确保日志格式统一，便于阅读

### 3. 实现步骤

#### 步骤1：创建后端日志工具
- 创建 `src-tauri/platforms/shared/src/logger.rs`
- 实现统一的日志记录函数
- 配置日志级别和格式

#### 步骤2：增强API响应处理
- 更新 `ApiResponse` 结构，确保原始数据正确填充
- 为所有平台实现增强版方法
- 确保原始数据在所有API响应中可用

#### 步骤3：为各平台添加日志
- 在 `douyu`、`douyin`、`huya` 和 `bilibili` 平台的所有方法中添加日志
- 记录请求参数、响应结果和错误信息
- 记录原始API响应数据

#### 步骤4：更新前端 `platformApiService.ts`
- 修改API响应类型，添加原始数据字段
- 添加配置选项，支持开启/关闭原始数据打印
- 在API调用中添加详细日志
- 打印原始API响应数据

#### 步骤5：增强组件日志
- 在 `FollowsList`、`player` 等关键组件中添加原始数据日志
- 添加调试开关，控制日志输出

### 4. 预期效果

1. **统一的日志体系**：所有平台使用相同的日志格式和级别
2. **详细的请求/响应日志**：包含请求参数、响应结果和错误信息
3. **原始数据可访问**：前端可以查看和打印API原始数据
4. **便于调试**：通过详细的日志记录，快速定位问题
5. **可配置的日志级别**：根据需要调整日志详细程度
